# M6.4 动画图作者工作区

顶部“工具/窗口 → 动画图工作区”打开独立深蓝画布。使用已导入角色的骨架/Clip UUID，
本机打开 `.ncmaanim` 或通过保存对话框选新文件。只接受严格 v1 和小写扩展名，不恢复旧图/场景格式。

## 本机编辑

1. 审阅精确文件路径/graph UUID，勾选后批准本机文件编辑，再开始草稿。
2. 搜索节点；拖拽、多选、框选、中键平移、滚轮锚点缩放；从输出引脚连到相同类型输入。
   Inspector 编辑节点、参数、状态、入口、转换和类型化条件；严格分页 JSON 是语义数据，不执行代码。
3. 草稿允许暂时未连完。准备保存时必须结构完整；检查候选的完整分页、旧/新 hash、资源 UUID/
   generation/hash及配对受众，勾选并批准显示的精确提案。
4. 本机提交保存进入唯一 Editor.Core 历史。一组草稿/拖拽归并为一次显式保存 Undo；
   手势释放不自动写文件。取消没有持久副作用，Undo/Redo重检原批准和当前资源/文件状态。
5. 已批准提案可显式准备独立真实角色预览，运行/暂停/单步和参数输入只操作该预览时钟。
   主场景/Play不推进、不重启；草稿变化关闭旧预览。关闭时释放GPU→pose/scene→资源租约。

保存是文件参与者事务：场景内容/tick不变，但完整文档历史会重装相同场景、改变 runtime World identity，
用户代码需重新按持久 UUID 获取引用。这不是预览直接修改 World。

## 外部 MCP

先在本机配对端点、打开图并批准图只读范围。`ncma.animgraph.propose` 使用稳定提案/元素 UUID，
最多64条closed语义操作，返回有界 diff/hash；不读磁盘、不批准文件、不采样或推进Play。
新建图由本机先选择不存在的精确路径并创建最小合法种子，再批准读取；Agent输入不接受文件路径。

`ncma.animgraph.transaction`只引用已准备提案和expectedAssetRevision，必须通过两道人工批准：

- 动画图区：审阅并批准精确候选、文件路径/旧新bytes hash和真实依赖闭包。
- 场景端点区：审阅精确请求与能力。动画图AI栏“返回场景端点审批”保留Agent提案，
  但禁止携带本机草稿；两道批准均完成后客户端重试原请求。

配对/端点权限不隐含文件权限。共享配对受众不是逐客户端ACL；每请求重检身份、受众版本、
read grant、60秒期限和Edit/asset revision。取消/显式撤销/重新配对/资源代次替换拒绝陈旧提案。
Agent不能配对/审批自己、Step/seek live Play、加载代码/Python、直接访问World/GPU或运行推理。
重复相同候选请求是幂等，提案ID内容变更或取消后复用拒绝。

## 预算与限制

操作64、输入48KiB/深度16、持久图1MiB；同时候选4、退休提案256、历史审批64、
批准依赖闭包4（每份沿用RuntimeAssetLoader 512MiB上限），选中节点64，搜索结果32；
zoom 0.2–2，pan ±65536。预算满后显式撤销/重开，不隐式扩大。
未保存的authoring preview不可嵌套或打包。真实用户FBX、人工视觉/DPI/IME/第三方客户端、
目标机预算与1小时长稳仍待验收。截图中的程序化二骨骼模型不代表完整用户角色效果。
