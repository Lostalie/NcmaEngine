## 2. 测试工程与分层

- Runtime.Tests：存储、固定步、差量结构、阶段守卫、准备/安装原子性。
- Scene.Tests：配置联合提交、格式/元数据与旧格式拒绝。
- Gameplay.Tests（已新增）：会话、生命周期、输入/时间/信号、脚本故障与重载。
- Editor.Core.Tests：完整文档历史、权限/范围、幂等、脚本局部配置操作、详情分页。
- Editor Transport/Mcp Tests（已新增）：管道、配对、队列、真实 stdio 子进程、错误与上下限。
- 既有 native/managed ABI、宿主/编辑器/FBX/动画 smoke：覆盖真实部署与外壳接线。
- Python 工具回归：inspect、manifest、独立动画 MCP、删除格式/桥接项拒绝。
- 人工客户端与 ImGui 验收：补足 UI 焦点、窗口控制、授权提示和第三方客户端兼容性。

测试不得依赖网络、模型 key 或 LLM 推理。真实客户端人工验收不替代协议自动测试。

## 3. 核心矩阵

| 领域 | 必须覆盖 | 判断依据 |
| --- | --- | --- |
| 模拟唯一性 | 一帧 0/1/8 步；30/60/144 FPS 等模拟时长 | Tick/固定结果到容差一致，非每渲染帧提交 |
| 时间边界 | NaN/负值/Infinity/超预算/溢出；严格与交互策略 | 非法请求零变更；丢时可查询 |
| 运行控制 | Play/Pause/Resume/Step/Fault/Stop/Restart | 单步恰好一次；不欠时；故障不自动继续 |
| 行为阶段 | 禁用绑定、OnUpdate 写入、生命周期抛异常 | 阶段守卫生效；回调不递归/不自动重试 |
| 输入 | 无步暂存、多步一次消费、失焦、ImGui 捕获 | 不丢首个边沿，不恢复误触发/卡键 |
| 插值 | 无 Transform、新建/删除、四元数、暂停/Step | 不写权威组件、不增加编辑 revision |
| 结构命令 | 创建/配置/删除顺序、容量、后置失败 | 当前步全成/全败；存活句柄不整体失效 |
| 信号 | 发送/消费/中止/容量/会话 epoch | 下一步可见；失败不半消费 |
| 故障原子性 | Prepare 各层失败、连续帧部分成功 | 本步不安装；此前成功步保留；无伪造 IO 回滚 |
| 程序集重载 | 预检失败、激活失败、重复重载/停止 | 保留/故障状态明确；可卸载引用有界 |
| 编辑基线 | 全配置 Undo、草稿、UUID、Dirty、文件关联 | M1.2 已交付行为不回归 |
| MCP 活动状态 | Agent 与用户依次编辑同一文档 | 同一 session/revision/历史，无独立场景 |
| MCP 默认权限 | 未配对/只读连接/越范围/未批删除 | denied 或协议拒绝且内容不变 |
| 历史风险 | 人工顶端条目、新建/打开、删除重做 | 范围/文档替换/批准检查不绕过 |
| 请求恢复 | 精确重试、冲突、缓存淘汰、断线/取消 | 只提交一次或明确未知，不自动覆盖 |
| 竞争场景 | 双客户端、用户拖动、Play/Stop、New/Open | 冲突确定；只读不泄露草稿；冻结不失效 |
| 资源边界 | 队列/输入/输出/日志/回执/连接上限 | 有界拒绝，无无限增长/协议输出污染 |
| 架构隔离 | owner thread、平台头、ABI、Python | 无新 native World、外线程修改或 Python gameplay |
| 旧入口清理 | .ncscene/旧 SceneSnapshot/旧 bridge | 明确拒绝，不 sniff/不 fallback |

确定性以相同构建、身份与输入序列为前提；不把 float 跨平台差异误判为所有系统都必须逐位一致。

## 4. 故障注入方案

在测试构建中提供可信内部故障点，不把故障注入暴露为 Agent capability：

1. 组件候选/结构索引准备失败。
2. Scene 绑定元数据准备失败。
3. 实例构造/生命周期回调失败。
4. 输入消费与 mailbox 候选准备失败。
5. 结果/历史/缓存准备失败。
6. Core 提交前撤权、revision 改变、文档 generation 改变。
7. 队列入队前满、等待过期、端点关闭。
8. 事务提交后 IPC 响应丢失。

每个故障比较完整引擎受管状态：已提交对象/组件/绑定、Tick、输入/mailbox 游标、历史、Dirty、文件关联、授权和回执。提交后断线必须记录“已提交但响应丢失”，不能回报为零变更。

不在生产测试中故意耗尽系统内存；用内部准备故障点替代可控分配失败，不宣称可以从任意进程级 OOM 保证恢复。私有脚本字段与外部 IO 另记录副作用，不纳入引擎原子回滚承诺。

## 5. 最小联合演示场景

使用测试生成的唯一 .ncmascene JSON v1，包含：

- 一个无 Transform 的空对象；
- 一个有 Transform 的 RotatorBehaviour 对象；
- 一个带两项 C# Behaviour、启用/禁用状态与四种标量 Export 的对象；
- 一个可信注册测试组件对象；
- 足够分页的对象与脚本配置，验证详情查询不依赖小场景。

演示顺序：

1. 编辑器打开场景，人工修改/Undo/Redo，验证保存指纹。
2. 只读 MCP inspect/对象详情/组件和 Behaviour catalog，默认事务被拒绝。
3. 用户批准精确提案，Agent 创建对象、设置组件、挂绑定、改 Export。
4. UI Undo，Agent 在有效授权下 Redo；validate 与内容一致。
5. 未批准 UUID 删除被拒绝；批准后删除，撤销/重做再检查权限。
6. 人工拖动未提交时 Agent 写入冲突；取消拖动没有新增历史。
7. Play 后固定步旋转、输入边沿与插值可观察；Agent 读编辑副本可用、写被冻结。
8. Paused 单步、注入故障、Stop；编辑场景/历史/关联/选择仍与 Play 前一致。
9. 运行中结构生成/删除、信号消费及重载失败通过单独 Gameplay fixture 验证，不要求完整角色渲染。
10. 提交后断开 MCP，恢复/查询同 requestId，确认没有第二次创建。
11. 关闭所有本次测试连接/进程；再启动无旧授权/旧输入/陈旧管道复用。

动画与 FBX 独立预览单独回归；不能把此场景演示当作已完成 GPU 角色或动作游戏。

## 6. 规范构建命令

在 F:\NcmaEngine 项目根目录运行：

~~~bat
Build.bat -Configuration Debug
Build.bat -Configuration Release
~~~

Build.bat 自行初始化 VS 工具链。实施时更新 scripts/Build.ps1/CMake 测试清单，让新增项目与程序集部署进入规范流程，而不是只在开发者本机手动运行。

必需证据包括 NcmaCore/NcmaNative/NcmaArchitectureTests 优先构建、CTest、Ncma.Managed/新托管测试、managed/native smoke、python -m ncma_tools.cli inspect .、Python 回归。不得使用 SkipTests 等跳过项作为最终通过证据。

构建产物放在 out/、bin/、obj/ 等忽略目录；主程序保持 out/bin/NcmaEngine.exe。不把 .vs、本机 .user 或临时客户端凭证纳入交付。

## 7. 性能与资源记录

记录机器/配置/场景规模/执行次数和 median/p95/max，不预设未经测试的 FPS 承诺：

- 0/1/8 固定步；0/64/1024 运行命令；组件/绑定数量的压力组合。
- Behaviour 与 System 各自耗时、每步/帧托管分配、插值视图大小。
- MCP 无连接/只读/写入/四连接满队列时的延迟和主循环耗时。
- 事务准备/安装、详情分页输出、回执/缓存/历史/日志占用。
- 重复 Start/Stop/Reload/连接断开后的弱引用、活动实例、队列和句柄数量。

软预算 2 ms 不等于一次大文档校验可抢占；需要呈现最长 Invoke 与游戏帧影响。若 M1 数据结构不能满足大场景需求，应诚实记录限制，把存储优化列为后续任务，不以未测“高性能 ECS”替代证据。

## 9. M1 完成定义

以下全部满足才标记 M1 完成：

- C# 是唯一场景与 Play 高层权威，固定步与生命周期真实接入当前编辑器。
- 引擎受管状态每步原子，故障与外部副作用边界清楚。
- 完整编辑文档、Undo/Redo、草稿、UUID、文件状态与 Play 隔离无回归。
- 本地 MCP 实际连接当前编辑器；人工/Agent 共用命令和历史，权限与风险不会被旁路。
- 稳定 Schema、结构化结果、幂等/冲突/容量/线程/关闭约束有证据。
- 旧代码/旧格式被真正移除，没有兼容逃生口。
- 构建/测试、人工验收、文档/manifest 与实现一致，新增代码零警告/错误。
