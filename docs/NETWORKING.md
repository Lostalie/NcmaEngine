# 独立网络系统架构

状态：架构约束已更新为独立 C# 服务；游戏网络运行时及服务接口均未实现。
C++ 只在有性能依据的传输内核中作为可选插件，Python AI IPC 不是游戏联机协议。
当前 stdio MCP 服务不是游戏联机系统，本设计也不自动授权远程编辑器访问。

## 系统边界

网络是可选的 C# 独立服务，不内嵌到 Actor、GameObject、组件或 Behaviour。
会话、协议、同步规则与身份映射不搬到通用 C++ 层；原生传输优化须证明必要性。
网络库应能脱离场景、渲染器、编辑器与脚本宿主运行；离线游戏不需要创建网络会话。

依赖方向如下，均为目标设计，不代表当前已有目标或接口：

```text
应用 / 游戏入口（组装与生命周期）
              |
     游戏同步适配层
        /           \
独立网络服务      C# 游戏模拟 / World
会话、消息、传输   场景、动画、物理
```

- 网络层不包含 SceneWorld、GameObject、Behaviour、组件、动画或物理 API，也不加载脚本宿主。
- 场景、动画、物理模块不包含网络头文件、不链接网络库，不因联机而改变基础数据结构。
- 应用适配层可以同时使用两个系统；它负责选择需要同步的数据，而非网络层遍历并复制场景。
- C# 使用独立服务/消息接口，不要求继承 Behaviour。Python 专长模块只经受控模块契约返回结果，
  不持有联机 World；gRPC/ZeroMQ AI 请求通道不等同于游戏网络服务。
- 传输库类型不进入 World/组件契约；若采用原生插件，仍用版本化 POD/句柄 C ABI，不泄露 STL/异常。

## 禁止的耦合

不在 GameObject、组件或 Behaviour 基类中加入：

- Replicated/自动属性复制标记、RPC 方法注解或按对象反射调用的远程方法。
- 网络 Role、Authority、OwnerConnection、连接回调或服务端/客户端专用继承层次。
- 自动网络生成/销毁对象、自动序列化整个场景或按组件类型决定传输策略。

游戏仍可实现“哪些状态同步、谁有控制权、如何处理远程动作”等规则，
但规则属于独立同步服务/应用适配层，不属于场景对象与组件的基础契约。

## 职责分配

| 层 | 职责 | 不负责 |
|---|---|---|
| 传输 | 连接、收发、传输后端及其可靠性能力 | 场景识别、组件访问、角色控制 |
| 会话与协议 | 会话状态、版本协商、消息编解码、大小/频率限制、有界队列 | 自动场景复制、游戏对象远程调用 |
| 游戏同步适配层 | 身份映射、输入序号与 tick、权限校验、状态快照、动作事件 | 修改 GameObject/Behaviour 基类、泄露传输库类型 |
| 应用入口 | 组装服务、启动/停止、离线或联机模式 | 让所有场景强制持有网络服务 |

网络接收工作只产生消息。适配层须检查身份、会话代次、消息格式、顺序与游戏权限，
在明确的模拟 tick 边界应用输入。网络线程/连接回调不得直接修改 C# World 或调用 Behaviour 生命周期。
发送路径也由适配层显式构造快照/事件，而不是读取任意组件字段。

## 身份、协议与生命周期

- 会话内网络实体 ID 与运行时 GameObjectId、持久资产/对象 UUID 分开。适配层维护映射，
  并校验实体代次/会话代次，避免断线、重连或句柄复用后旧消息影响新实体。
- 网络 ID、连接句柄、网络角色与同步缓存不写入 `.ncmascene`；保存/加载场景不建立网络会话。
- Wire 消息使用独立版本化 schema，规定编码、长度、字段范围和兼容策略；不直接传输内存布局或场景文件。
- 连接/认证/重连状态属于网络会话，游戏对象的创建、销毁与控制权变化由应用规则显式处理。
- 停止游戏/替换场景时先停止适配层消费并解除映射，再释放场景；网络会话可按应用选择关闭或继续存在。
- Play 的网络行为必须显式配置，默认离线；网络产生的实时游戏状态不能改写 authored 场景或其编辑器撤销历史。

## 动作游戏同步策略（均未实现）

优先传递带 tick/序号的玩家输入与必要状态，而非逐组件复制每一帧的 Transform 或骨骼姿势。
服务端权威、客户端预测、纠正/重演、快照插值、动作事件同步、命中补偿等，
后续作为独立游戏同步服务按需要设计；不据此宣称当前模拟已具备跨平台确定性。
动作状态与通知处理由本地 C# 系统负责，性能关键姿势内核可用 C++ 插件；
收到动作消息不意味着网络层能直接访问动画组件。

## 后续实现与验收

1. 明确联机场景、拓扑、平台、认证/加密、可靠性与预算要求，再选择传输后端；目前不指定 UDP/TCP 或第三方库。
2. 建立独立库及无场景依赖测试：双端 loopback、编码版本、大小限制、有界队列、断线/取消。
3. 定义版本化消息与 C# 独立服务接口，再接入应用入口；仅必要的原生插件需要 C ABI。
4. 建立首个显式输入/快照适配层，验证 tick 边界、权限、会话/实体失效与离线模式。
5. 加入丢包、重复、乱序、延迟、重连与恶意输入测试；后续再实现动作游戏预测策略。

验收必须证明网络库不依赖 Scene/动画/物理/脚本宿主，场景和模拟也不反向依赖网络库；
未配置网络服务时，现有单机编辑、脚本 Play 和动画流程应保持可用。
