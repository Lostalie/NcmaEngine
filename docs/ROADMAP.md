# NcmaEngine 开发路线图

更新：2026-10-16。依据当前源码依赖、阶段合同和实际交付记录重新整理。

**已确认新顺序：M8.2 收尾 → ECS 重构 → M8.3 及后续 → M9。** M8.2 最终同源码完整 Debug/Release 与部署核验已通过，见 [交付记录](M8_2_DELIVERY_REPORT.md)。ECS E0、E1-A 已交付，E1-B 身份/单一门面迁移已完成并通过双配置自动门禁（[交付证据](ECS_E1_B_DELIVERY.md)）；下一阶段 E2，不直接跳到 M8.3。

本文是当前优先级与状态总览；旧计划和交付报告保留失败证据与历史决策，不以其中早期“下一步”自动启动任务。当前架构记录见 [架构合同](ARCHITECTURE.md)，ECS 为下述新目标，不是已有实现。

## 1. 固定方向

- C# 是主引擎和唯一游戏逻辑语言，拥有 World、组件、调度、场景/资产元数据、编辑业务及唯一事务/Undo。
- 新目标：C# ECS 是唯一运行时数据存储；GameObject 是同一 Entity 的高级封装，不复制组件状态、不建立双运行时同步。源码已采用强类型池和代次 Entity，仅保留 Ncma.GameObject 高层门面；低层 Runtime.GameObject 及旧 API 已迁移删除，没有兼容壳；完整 ECS 和性能验收尚未完成。
- C++ 是性能插件与原生表现层：渲染、物理、经测量需要的动画/导入/数学内核及现有 Dear ImGui。旧 C++ Editor/World/CLR 桥已删除。
- Python 是可选异步专长模块，不挂 Behaviour，不拥有 live World。M8.2 gRPC 工具 worker 已有候选代码；pythonnet、ZeroMQ、模型推理未实现。
- 场景采用扁平 GameObject 列表、空容器 + 组件，Transform 可选；不恢复 Node、Actor 复制、对象父子树或变换继承。
- AI 深度参与场景、资产、动画、UI、工具和托管扩展，但与人工共用领域命令、授权、预检、事务与 Undo；不提供通用执行后门。
- 一个共享渲染框架，两条独立产品管线：2D 足够轻，3D 默认可用、简单定制。纯 2D 不强制初始化/部署 3D 资源。
- 本版本只交付 DX11；Vulkan/OpenGL 保留契约扩展，下版本实现。不继续承诺 DX12。
- M9 先实现 Windows 正式导出；微信小游戏、Android、iOS 仅保留平台扩展目标，后续版本实施。
- 网络保持独立可选服务，不与 GameObject/组件耦合。模块 gRPC 不等于多人游戏网络。
- 保留用户图片确定的统一编辑器风格；移除类 Figma 参考，不改变独立 UI 制作/HUD 目标。

## 2. 状态口径

| 状态 | 含义 |
| --- | --- |
| 已实现切片 | 有实际实现和对应证据，仅覆盖列明范围 |
| 自动候选已交付 | 该阶段规定的自动回归/包检查通过，不等于生产验收 |
| 实施中 | 代码或定向验证已有，阶段完整门禁尚未通过 |
| 未实现 | 设计目标，无正式可用实现 |
| 待验收 | 实现存在，但相应人工、素材、目标环境或性能证据缺失 |

不使用“接口已存在”“MCP 已连通”“能打包”替代真实推理、完整编辑功能或用户游戏发布。自动审计通过不改变 `h8_accepted` 等人工门禁。

## 5. M8 剩余执行方案与 ECS 前置阶段

### M8.2 收尾：先完成当前片，不抢跑下一片

状态：以下自动门禁已完成，详见交付记录；作为今后阶段的收尾规则保留。

1. 保留首轮失败证据，核对最终源码冻结和完整 Debug 结果。
2. 恢复工作后，对同一源码执行完整无 Skip Release；原测试、审计、备份/日志恢复和默认产品独立性不得降级。
3. 核对独立客户端清单、搬移真实加载、Python 进程退出、真实调用成本和默认产品不携带可选依赖。
4. 补交付记录；仅全部规定门禁通过后按既有授权提交推送。
5. 此片只能声明“真实工具模块通信可用”，不能声明“模型已接入”。

### ECS 重构：M8.2 交付后、M8.3 开始前

目标是 C# ECS 唯一权威存储，GameObject 为 Entity 的高层入口。首期建议强类型组件池/Sparse Set、单线程确定性 Systems、有界 Query 和受检增量写集；E0 实测后确定具体存储选择，不提前承诺性能倍数。

| 步骤 | 范围 | 验收重点 |
| --- | --- | --- |
| E0 合同与基线 | 身份/代次、读写可见性、权限/事务和现有性能基线 | 覆盖 100/1000/4096 对象、角色/动画/纯2D；记录固定步、P95/P99、分配/GC/内存，先约定目标 |
| E1 Entity 与组件池 | World 身份+索引+代次、强类型存储、GameObject 同实体封装 | 跨 World/删除复用/恢复后旧引用拒绝；UUID 与既有场景往返保持 |
| E2 Query 与结构命令 | 有界类型查询、增删组件/创建删除的批次 | 安全边界执行、全批预检、迭代失效与确定性顺序；不得部分提交 |
| E3 增量固定步 | 消除热路径全量文档构造，保留已提交读取与暂存写入 | 输入/信号/Behaviour/组件权威语义等价；失败回滚范围明确、物理仍 fail-stop |
| E4 子系统迁移 | 角色、动画、渲染提取、场景/编辑和现有 AI 查询适配 | Editor/Player/Headless 联合回归；复用批量原生 ABI，不给 Agent 新写权限 |
| E5 验收与旧存储清理 | 完整 Debug/Release、包/恢复检查、性能对照、精确旧实现清理 | 不降低原有测试与安全规则；清理后复测，证明目标收益且无不可接受的小场景退化 |

保留独立 C# Behaviour、唯一 EditSession/Undo、扁平场景和可选 Transform。不同时改场景格式、Undo 存储或引入多线程；不开放不受限的 ref 写入，不恢复旧格式/类型兼容。编辑文档可继续使用完整快照，不能把每帧优化与编辑历史重写捆绑。

ECS 容量提升不自动放宽文档、Agent、插件和资产预算；真实素材、人工、目标机、自包含和长稳门禁独立保留。完成约定重构门禁后才进入 M8.3。

### M8.3 领域提案闭环

前置：M8.2 已交付，ECS 重构 E0–E5 已按约定门禁验收。

- 将可选模块结果接回现有场景、动画、UI、资产领域服务；先覆盖已具备真实读写业务的操作。
- 请求绑定精确项目/会话/文档代次/revision/权限；返回有界结构化提案。
- 先做 schema/语义验证和 dry-run/diff，再由本地人类批准同一命令/事务。
- 资产写入与 Prefab 操作必须先补对应 M3 业务，不允许文本占位“成功”。
- 验收：有效提案单次提交/Undo/Redo，陈旧/撤权/换场景拒绝，失败不留部分修改；人工与 Agent 操作语义一致。

### M8.4 真实模型与正式 AI 工作区

- 由用户选择一个真实本地或远程模型服务，不同时铺开所有供应商/传输。
- 凭据、网络外发范围、模型/依赖下载与付费分别审批；默认关闭，不在日志或报告暴露秘密。
- 面板显示真实未连接/准备/运行/取消/故障状态、批准范围、结果与证据；不把 MCP 状态当推理状态。
- 验收：真实模型在已批准范围完成一个场景/动画/UI 制作任务；超时、断连、取消与拒绝均可解释，不阻塞 tick。

### M8.5 托管扩展

- 使用可信启动注册的 C# 扩展契约、版本/依赖校验、明确生命周期与关闭规则。
- AI 可提出扩展方案或代码补丁；审查、编译/测试、安装/重启分别受控。
- 不开放任意程序集路径加载、eval、shell 或运行中私自提升权限。
- 验收：错误版本/依赖拒绝，重复注册与卸载顺序可测，资源先失效再释放；默认运行产品不受影响。

### M8.6 可审计开发工作流

- 串联观察、计划、精确审批、领域命令或已批准补丁、构建/测试、结果回执。
- 复用已有 workflow ledger，不把它扩张成第二个命令执行器/历史。
- 明确取消、部分成功、外部 IO 和代码变更不能随 World Undo 自动回滚；不得覆盖用户后续编辑。
- 验收：每步可追踪，失败可停止与受检恢复，无隐式安装/发布/Git 写入。

### M8.7 联合验收

- 默认无 Python 产品与显式启用模块产品分别验证；客户端/worker 独立搬移，缺件/改变包拒绝。
- 场景、动画、UI、资源和扩展各选真实任务，关联最终产物/命令回执/测试证据。
- 模块启动/故障/关闭、取消/背压、身份/权限撤销及资源泄漏联合测试。
- 测量端到端延迟、CPU/内存/分配与帧影响；测试驱动轮询耗时不能冒充纯 RPC 延迟。
- 完整 Debug/Release、实际客户端人工验证、长稳分别记账；未通过不标生产就绪。

## 7. 推进与验收规则

- 每个小阶段：明确范围 → 实现 → 定向测试 → 必要的完整双配置回归 → 记录剩余门禁 → 提交推送 → 下一片。
- 用户确认的新顺序覆盖旧“M8.2 后直接进入 M8.3”的安排；本轮计划更新不等于已开始重构。
- 一次只推进一个闭环，不并行扩张模型供应商、传输后端与新发布平台。
- ECS 方向已确认，但具体存储/提交优化仍以 E0 剖析和回归为依据；2D/3D 效率用 CPU/GPU/分配/上传/驻留数据验证，不预先承诺零拷贝或性能倍数。
- 人工、用户素材、目标机、自包含、完整性能、1h 和历史 File.Replace/空缓存等故障调查分别保留，不能由自动测试替代。
- 文档清理不删除代码、测试、SDK、用户资产、失败证据、部署备份或无关 IDE 设置。

M8.2 自动候选门禁和 **ECS E0 合同与自动基线**已完成（[详细合同](ECS_IMPLEMENTATION_PLAN.md)、[基线记录](ECS_E0_BASELINE.md)）；本地时间噪声不支持直接判断 5% 小场景退化，完整性能门禁仍开放。E1-A 强类型池和 E1-B 代次身份/单一门面已接入源码唯一 World；所有低层消费者使用 World + Entity，Runtime.GameObject/旧入口已删除并通过同源码双配置各 89 项 CTest，见 [E1-B 记录](ECS_E1_B_DELIVERY.md)。正式 EXE 保持 M8.2。下一步 **E2 Query 与有界结构批次**，再推进 E3–E5，通过后恢复 **M8.3 及后续**，最后推进 **M9 Windows 发布**。
