## 1. 目标和非目标

扩展由用户审查的 C# 源码构建、宿主可信启动代码显式注册，用于编辑器工具和引擎功能扩展。C# 拥有大部分引擎功能；C++ 仍只是性能关键插件，Python 独立模块不改为游戏脚本。

- 新 `Ncma.Extensions` 与推理、Python、MCP、场景 World 无依赖，默认 Editor/Player 不引用、不启用它。
- 扩展注册不替代 `CompositionRegistry.Build()`、原业务命令/事务、workflow ledger 或权限系统。
- AI 只能提出扩展方案和待审代码，不能安装、加载、批准自己、执行任意 shell 或绕过原权限。
- 元数据与版本兼容不等于程序集签名验证或安全隔离。可信进程内 C# 代码本身具有宿主权限，不把此 API 宣称为恶意插件沙箱。
- 本版本不做目录扫描、任意 DLL 路径加载、Assembly.Load/eval、动态下载、运行时热替换或通用可卸载程序集环境。停用资源与卸载 CLR 程序集不是同一承诺。
- 本机 AI 配置、连接参数和密钥不提交，不用于扩展身份或依赖元数据。

## 3. A 的精确合同

- `ExtensionVersion`：稳定版本三元组，major 1..65535，minor/patch 0..65535，默认零结构体拒绝；不解析 prerelease、通配符或浮动版本。
- 描述符：规范 ASCII 小写 ID（最多 96 字符）、扩展版本、最低宿主 API、显式依赖集合。宿主 API 必须同 major，minor/patch 不低于最低值。
- 每条依赖为同一 major 内的闭区间；依赖必须在本次宿主显式提供的完整集合中。不自动查找、安装或下载。
- 最多 64 扩展、每项 16 依赖、总计 256 条边；超限、重复（包括同一实例重复注册）、空项、缺依赖、不兼容、自环/环路明确拒绝。
- 输入先复制，描述符与依赖对象不可变，返回只读计划；失败不返回半成品，不影响先前计划。无回调，因此编译计划无扩展代码执行副作用。
- ID 和邻接表使用 Ordinal 排序，确定性 DFS 拓扑排列；依赖在使用者之前。不是任务调度、热路径 API 或 0B 性能承诺。
- `ExtensionRejectedException` 提供稳定 code、可选扩展/依赖 ID，不拼接任意异常正文或配置秘密。
- A 只给出元数据计划，尚无工厂、宿主启动/关闭、资源授权、Editor UI 或实际扩展安装。计划不是授权票据。

## 4. B/C 的关键边界

创建工厂只能来自精确受信源码装配，不能从 AI 文本、manifest 类型名或路径反射生成。完整预检之后才允许构造/Start；构造异常也必须记录已创建实例所有权，不静默重试。

关闭按依赖逆序，先使资源访问代次失效，再关闭依赖者；关闭失败不得先释放其依赖。复用 `ApplicationLifetime` 已有保留/重试原则；具体适配需审核异常聚合、重复关闭、线程和吞掉重入异常的行为。不能让扩展通过异常或重入恢复已撤销资源。

扩展贡献组件时只汇入现有程序集聚合与 `CompositionRegistry.Build()`；贡献编辑命令时只调用现有能力受检事务。未设计对应业务权限前不开放泛型服务定位器、任意 World 或 EditSession 写访问。

代码补丁与安装影响文件系统，不能伪装成 World Undo。复用现有隔离构建、证据和受检部署边界；原 workflow ledger 仅支持其封闭场景工具清单，**不是现成的源码补丁审批/文件执行器**，不扩权冒用。文件来源捕获、完整人工审阅与后续构建/安装票据需要单独显式接线；安装前精确确认来源和变更，失败保留证据，不修改当前安装或用户后续编辑。

## 7. B 生命周期实施记录（2026-10-27，已编译、未验证）

### 7.1 分层与启动

新增可选 `Ncma.Extensions.Hosting`，引用元数据核心和原 `Ncma.Application`；其后者传递依赖 Scene/Assets/Runtime，因此不能宣称宿主适配库不包含任何引擎依赖。`Ncma.Extensions` 本身仍保持独立。默认 Editor/Player 未新增引用，也没有实际安装或启用扩展。

`ExtensionApplicationService` 是一个普通 `IApplicationService`，内部使用原 `ApplicationLifetime` 管理按依赖顺序排列的服务包装器。原生命周期实现未修改；外层应用可将整个扩展组当一个服务管理。

- 构造时检查注册集合完整、唯一，描述符必须是计划中的精确不可变实例；复制输入，无工厂调用。
- 工厂为可信 C# `Action<ExtensionConstruction>`。必须先 `Attach(instance)` 成功转移所有权，再执行后续可能失败的初始化；包装器在原 `Start` 调用前已登记为受管服务。
- 工厂在 Attach 后抛出时，宿主仍持有实例，原生命周期可清理；未 Attach 的实例、被拒绝的第二实例、构造函数中尚未返回的资源仍由工厂负责，不能假称这些外部副作用已回滚。
- 弱键归属表拒绝同一活实例同时归属于两个扩展/宿主组；关闭成功才撤销归属，失败保留。它不是程序集加载或权限注册表。
- 工厂单次消耗，Start 完成/失败或提前关闭后清除剩余工厂引用；不得重启同组或自动重建实例。

### 7.2 对外访问与关闭

扩展在 Start 收到 `ExtensionAccess`；只有**整个组启动成功**后 `RequireActive()` 才可用。资源门面必须在每次入口调用此检查。凭据包含独立会话身份和精确对象绑定，旧组关闭后不会因同 ID 新组启动而恢复。

关闭开始时先把整个组置为 Closing，所有访问立即失效，再由原生命周期逆序释放。启动失败同样在原补偿调用前失效。B 只实现访问守卫，并未把真实场景/编辑器资源挂入门面；不声称任意可信代码持有的原始对象引用已经被 CLR 撤销。

| 情况 | 所有权与访问 | 后续操作 |
| --- | --- | --- |
| 全部 Start 成功 | 访问有效，原生命周期持有全部服务 | 正常 Dispose |
| Start 失败、补偿成功 | 访问无效，无保留服务，诊断仍保留 | Dispose 收尾，不允许重新 Start |
| Start 补偿或普通关闭失败 | 访问无效；失败实例和未释放依赖保留 | 可信宿主显式 `RetryClose()` |
| 外层生命周期随后再次 Dispose | 已有关闭失败时明确拒绝，不重复调用扩展 Dispose | 先显式完成组 RetryClose，再关闭外层 |
| 显式 RetryClose 成功 | 全部释放、Closed；旧失败诊断仍可见 | 幂等 Dispose，旧访问永久失效 |

拒绝自动二次关闭很重要：原外层 `ApplicationLifetime.Start()` 在组 Start 失败后会调用组 Dispose。若组内部补偿已经失败，这个外层清理不能成为未经确认的再次释放尝试。

重试只重试尚未释放的实例，不重复释放先前成功关闭的服务；扩展必须能承受失败/不确定完成后的重复 Dispose。被保留对象不会被强制卸载。同步可信回调不受此协议的执行时长隔离，不能宣称支持任意挂死插件的安全终止。

所有宿主变更/诊断操作限制 owner 线程；回调内宿主重入即拒绝，即使回调吞掉异常也判失败。过期 Construction 的 Attach、重复 Attach 和跨组实例复用拒绝；Access 在关闭时被拒是预期失效，不当作新的宿主重入。

## 8. C 首片：显式可选编辑器工具（2026-10-27）

## 10. C3-A 精确源码补丁数据合同（2026-10-27）

### 本片实现范围

新增 `Ncma.Extensions/ExtensionSourcePatch.cs`，仍处于独立元数据合同库中，不引用编辑场景、模型或文件执行器。四种不可变数据类型：

- `ExtensionSourceStamp`：工作区会话 UUID、来源 revision、完整源码/构建输入 SHA-256。当前由可信宿主调用方提供；不是本库实测的磁盘树证明、签名或授权。

- `ExtensionSourceChange`：一个路径的完整 before/after，明确新增、替换或删除；无变化、两侧路径不一致拒绝。不处理模糊补丁、行号重定位、自动合并或隐式 rename。

边界：最多 16 文件，逻辑路径 240 字符，每个 before/after 最多 64 KiB，所有两侧合计 256 KiB。仅支持可移植 ASCII 相对 `.cs` 路径；拒绝绝对路径、反斜杠、ADS、隐藏/上级段、设备名、通配符、生成目录 bin/obj/out、大小写重复和文件/目录前缀冲突。**这些只是逻辑路径规则，不证明真实文件系统包含关系，也不检查符号链接、junction、hardlink 或竞争条件。**

`RequireCurrent` 比较调用方提供的新来源戳及精确文件集合：包含新增目标的显式“不存在”，文件数/集合/大小写/存在状态/字节必须完全一致，拒绝遗漏、多余、重复和过期内容。失败不修改已构造提案。**它不读取当前磁盘、不保证快照真实或新鲜、不消费审批票据、不授权后续 IO，也不消除验证与写入之间的竞争。**

## 13. 捕获副本成为唯一源码输入（2026-10-27）

### 身份不能混用

历史 `ExtensionSourceStamp` 纯数据模型的 `RequireCurrent` 仅比较调用方提供的数据；后来的文件系统版 `ExtensionSourceCapture.RequireCurrent()` 已检查真实文件/目录身份与内容。但这种来源检查仍不能证明编译器使用了审阅内容。因此保留来源 stamp 作为溯源信息，**不再用它与全工程内容指纹作相等比较**。

现在的绑定链是：人工审阅捕获字节 → `.nccapture` 文件 SHA256 → 完整构建副本 `capture.json` → `captureManifestSha256` → 构建/发布回执。`capture.json` 中的 `sourceInputsSha256` 使用既有 `ncma-source-inputs-v1` 编码，针对**实际副本的完整文件清单和内容**计算；它与局部来源身份是不同含义，不能相互替代。

### 捕获与编译分成两步

1. 实际 Editor 完整逐页审阅后，可指定新 `.nccapture` 文件并显式导出。`CopyBuildBundle/ExportBuildBundle` 只序列化已经保存的 before/after 字节，**不重读 SourceRoot/CandidateRoot**。创建新文件、不覆盖已有文件；父目录按原无重解析点/拒绝删除句柄规则固定。不会编译、安装、上传或批准自己。
2. `Capture-ExtensionBuild.ps1 -ReviewBundle <路径> -ExpectedBundleSha256 <UI显示哈希>` 将工程其他输入一次性捕获到 `out/captured-build/<id>/source`，并叠加审阅包中的 after 图像。原目录只在这个明确的“捕获步骤”中读取。审阅包路径须是引擎仓库相对路径，例如 `managed/SomeProject/Feature.cs`；不属于捕获项目或显式源码链接的文件拒绝。before 与本次完整基线不一致时，捕获失败，要求重新审阅，不悄悄移植补丁。
3. 此后构建只接收 `-CapturedBuildRoot <id目录>`，项目、链接源码、生成器源码、CMake 和原生源码均来自副本。修改原目录不会改变此轮输入；副本损坏会拒绝，不从原目录补文件。无审阅包参数时，只捕获当前开发基线，不能声称应用了某份人工审阅补丁。

完整输入选择补齐了旧 AI 清单漏掉的 `tools/`，以及已存在的根编译属性/目标/编辑配置文件。当前上限 65536 项、单文件 64 MiB、总读取 512 MiB；局部审阅仍为 16 文件、每图像 64 KiB、总 256 KiB。所有文件使用实际复制，不创建指向原目录的 junction/symlink。

### 编译和发布接线

- 生成 `capture.props`，使用显式 C# 文件清单，关闭默认 Compile/None 通配发现；原项目中的显式链接仍保留。后添加的 `.cs` 不会进入编译。配方哈希也由捕获清单绑定。
- 编译期间固定副本文件与父目录句柄，拒绝文件写入/替换、硬链接和重解析点。失败保留副本和日志，不自动回退原源码。
- `Prepare-ExtensionVerification.ps1` 和 M8.5 Compile 默认先捕获；可传同一个 `CapturedBuildRoot` 复用。`Prepare-AiVerification.ps1` 增加同名参数，M8.5 入口显式传入同份捕获；独立 M8.4 旧诊断模式不是这条扩展构建凭据。
- `Package-M2_7.ps1 -IncludeExtensions -CapturedBuildRoot ...` 从副本发布托管产品，并在捕获目录的独立 native 构建目录中配置、编译 C++，不借用传入的旧原生插件作为构建结果。原 `NativePluginRoot` 参数仍作旧调用位置校验，捕获分支使用自己生成的路径。
- 扩展索引、各产品 manifest、编译与验收记录绑定 `capturedBuildRoot/captureManifestSha256`；索引另记录 `reviewBundleSha256`。安装审阅和确认从捕获清单取输入身份，不再重新计算当前工作区哈希来替代它。缺少捕获绑定的旧包索引被安装入口拒绝，旧证据不补盖新戳。

这是可信本地构建的源码输入固定，不是恶意 MSBuild/C# 沙箱，也不是整个工具链的字节级可复现保证。SDK、编译器、NuGet 包缓存和系统库仍是外部构建依赖；不宣称已将它们全部快照或隔离。人工审阅不授予任意命令/加载/MCP 权限。
