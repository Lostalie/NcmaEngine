# FBX 角色导入：首个可验证流程

当前链路：FBX → C++ 资产导入器 → 骨架/蒙皮网格/动画库 → 编辑器 CPU 蒙皮线框预览。
使用固定版本 ufbx 0.23.0，源码与许可证位于 `engine/sdk/ufbx`，构建不联网。

## 使用

1. 运行根目录 `Build.bat`，启动 `out/bin/NcmaEngine.exe`。
2. 打开 Window > FBX Character Import，点击 Open FBX 选择角色文件。
3. 或点击 Load Test Character，加载随仓库提供的二进制测试角色。
4. 选择动画片段，使用 Play/Pause、Step 和 Orbit 查看网格与骨架。
5. 本窗口的 Undo/Redo 可撤销导入、片段切换和播放控制；导入失败保留原角色。

该窗口独立于 Action Animation Lab 和场景撤销历史。打开它时暂停主 PBR 预览，
避免当前直接写入交换链的场景绘制盖住浮动窗口。关闭后恢复。
导入目前同步执行，大文件/长动画可能阻塞编辑器；异步导入与取消属于后续工作。

Python 工具可读取导入报告，不保存或修改资产：

```powershell
$env:PYTHONPATH = 'F:\NcmaEngine\python\src'
python -m ncma_tools.cli import-fbx 'F:\Characters\Hero.fbx' --root F:\NcmaEngine --sample-rate 30
```

输出 JSON 包括骨架/网格/片段 UUID、骨骼数量、网格统计、动画长度、单位和警告。
它通过角色 C ABI v1 调用 C++，不是 Python 游戏组件。没有新增任意脚本执行入口。

## 已实现

- ASCII 和二进制 FBX；中文、空格文件路径；扩展名大小写不敏感。
- 转换到右手系、Y 向上、米制；保留必要的父节点、骨骼及变换辅助节点。
- 多边形三角化，逐角点位置/法线/UV，以及逐三角形材质槽；缺失法线由解析器生成。
- 读取 FBX 几何到骨骼绑定矩阵，支持线性/刚性蒙皮。取最强四个影响并归一化；
  超出四个影响或无权重顶点会给出警告，无权重顶点跟随网格节点。
- 通过 FBX 求值器处理动画变换，默认 30 Hz 采样动画栈，保留精确终点并归零片段时间。
  导入片段默认循环，不自动提取根运动；自动创建 BindPose 片段。
- 导入结果不可变，复用现有动画播放器；CPU 预览带橙色骨架叠加，最多绘制一万三角形。
- 传入同一个资产 UUID 的同结构重导入保持子资产 UUID。编辑器重导入当前同一路径时
  复用身份；尚无持久化资产数据库，换文件/重新启动后的身份并未保存。
  结构改变时需要未来的子资产映射，不能保证所有子资产 ID 不变。

## 明确限制

只接受含蒙皮三角网格的角色；不作为通用静态模型导入器。
暂不支持双四元数、多蒙皮变形器、实例化蒙皮网格、Morph Target、贴图读取、
完整 PBR 材质转换、动画压缩、自动重定向、FBX 通知轨道和角色根骨骼配置。
运行时 TRS 要求正缩放，无奇异缩放/反射/剪切；不符合的变换会拒绝，需在 DCC 中整理导出。

默认预算：源文件 256 MiB、200 万输出角点、200 万动画关键帧、1024 个骨骼/辅助节点，
单片段最长 600 秒，采样率 1–120 Hz。解析器临时/结果内存限制分别为 256/512 MiB；
不读取 FBX 引用的外部文件，不提取内嵌贴图。预算不能代替处理不可信文件的进程隔离。

当前没有把角色写入资产数据库/场景，没有 SkinnedMeshComponent，也没有 GPU 蒙皮。
C#/MCP 动画控制接口仍作用于独立程序化实验室，不能控制这个 FBX 窗口。
后续先用实际游戏角色验证，再做资产保存、DX11 GPU 蒙皮和场景组件绑定。

## 回归验证

`Build.bat` 包含 FBX 原生测试、隐藏编辑器导入/播放/撤销/重做测试以及 Python 工具测试。
使用上游 Blender 导出的 ASCII 6100 与二进制 7400 测试角色，逐角点对照 ufbx 的
绑定姿势和动画姿势蒙皮位置（误差小于 0.002 米），并验证层级、索引、权重、身份、
Unicode 路径、无效输入及预算拒绝。文件来源/哈希见 `tests/assets/fbx/README.md`。
这不代表已验证任意来源的 FBX 角色；用户真实角色仍需兼容性测试。
