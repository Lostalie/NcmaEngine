## 3. 固定架构边界

- C# 拥有唯一 World、游戏逻辑、Play 调度、场景配置、编辑命令及活动编辑器 AI 接入。
- C++/Dear ImGui 外壳暂时保留，只提交输入/控制意图、泵送托管工作与绘制复制的视图；不另建调度器、场景或撤销栈。
- Python 只保留可选 AI/工具/特殊模块，不增加游戏脚本，也不作为本阶段 MCP 的强制运行依赖。
- GameObject 为扁平空容器，组件可选；不加入 Node、父子对象树或自动 Transform。
- 编辑态 Agent 与人工修改共用 Editor.Core；运行态命令只修改 Play 副本，不进入编辑历史。
- IPC 后台线程不能调用 World、EditSession 或脚本；必须排队到所属线程的安全边界。
- 不添加旧 .ncscene、旧 SceneSnapshot 的兼容、迁移或备用读写入口。
- ABI 不传 STL、CLR 引用或异常；持久化身份使用 UUID，运行句柄不能保存。

## 5. 关键设计选择

1. 固定步承担可变游戏模拟；OnUpdate 只读 World，供渲染帧呈现使用。这是建议的玩法语义调整，必须迁移现有示例并明确拒绝旧式帧内写入。
2. 默认固定步为 1/60 秒，最多追赶 8 步；headless 严格模式与编辑器交互模式明确区分，丢弃时间必须结构化报告。
3. 每步原子性覆盖引擎管理的组件、结构、脚本绑定元数据、信号消费/发送及回执；不承诺回滚脚本私有字段、构造器副作用和外部 IO。
4. MCP 采用 C# stdio 辅助进程，经 Windows 本地 named pipe 连接当前编辑器；不复制场景，不通过外部线程直接调用编辑模型。
5. MCP 默认只读。工具 Schema 与风险只是描述，不等于授权；授权由用户在编辑器内给出。
6. M1.4 默认检查编辑文档；Play 时编辑文档仍可只读查看，但不可写入，也不提供 Agent 操纵运行副本的旁路。
7. 多次请求仅在有界缓存和当前会话内提供重试去重，不宣称跨进程崩溃、缓存淘汰后的永久 exactly-once。
